# AgentScope + Qwen: вопросы по Хабру

Три отдельных агента на одной модели: генератор пяти вопросов → ответчик → валидатор.
Четвёртый этап — Python-проверка наличия цитат. Общей памяти между агентами нет:
каждый получает только исходный фрагмент и необходимые результаты предыдущего этапа.

Источники (полные тексты сохранены локально в `data/`, без комментариев):

- https://habr.com/ru/companies/ruvds/articles/724066/
- https://habr.com/ru/articles/900440/

## Запуск

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env  # только если .env ещё не создан
```

По умолчанию используется `Qwen/Qwen2.5-7B-Instruct-GGUF:Q4_K_M` на
`http://127.0.0.1:9931/v1`, без ключа. Для сервера с авторизацией можно задать
`MODEL_API_KEY` в `.env`. Старые переменные `GEMMA_*` больше не используются.
Ключ не сохраняется в отчётах; `.env` исключён из Git.
Сервер должен быть запущен с `-c 8192`; клиент объявляет тот же размер контекста,
но не меняет параметры уже запущенного llama.cpp.

```sh
.venv/bin/python main.py
.venv/bin/python main.py --article data/900440.json
.venv/bin/python main.py --questions-from results/20261025-230717-434928/questions.txt
.venv/bin/python -m unittest -v
```

Обновить скачанные статьи: `.venv/bin/python download_articles.py`.
Другой сервер или модель: параметры `--base-url` и `--model`.
При `--questions-from` Qwen сначала генерирует собственные вопросы в `questions.txt`,
а отвечает и проверяет ответы на фиксированные вопросы из указанного файла.
Они сохраняются в `report.json` вместе с именем модели и параметрами сравнения.

## Что проверяется

- Пять вопросов и ответов по источнику.
- Вопрос 6: отсутствующий в статье пароль сервера. Ожидается отказ от выдумывания.
- Ответ 7 намеренно ложный: «Индексы никогда не занимают дополнительное место».
  К нему приложена настоящая цитата: валидатор должен проверить смысл, а не только наличие цитаты.
- Python проверяет JSON, полноту и уникальность id, точное наличие цитат
  (с нормализацией пробелов). Приняты только `supported` с найденной цитатой.

`results/<время>/` содержит исходный фрагмент, сырые ответы трёх агентов,
`report.json` и читаемый `report.md`. Код выхода: 0 — оба контрольных случая пройдены,
2 — контроль не пройден, 1 — ошибка запуска или структуры ответа.
Успех контрольных случаев не означает, что все остальные ответы верны.

## Ограничения

Для небольшого первого эксперимента обрабатываются первые 8000 символов выбранной статьи;
размер фрагмента и полный размер явно указаны в отчёте. Проверяется соответствие этому
фрагменту, а не научная достоверность статьи. Цитата сама по себе не доказывает смысл
ответа, а одинаковая модель в разных ролях может повторять ошибки.
Если модель вернула неправильный JSON, запуск остановится и сохранит сырой ответ:
результат не исправляется незаметно. На этом этапе нет автоматического цикла доработки.

## Первый реальный прогон

`results/20261025-230717-434928/`: сервер и вся цепочка отработали.
Модель приняла пять обычных ответов, корректно отказалась выдумывать пароль,
но неверно классифицировала ложный ответ про место для индексов.
Ручная проверка также нашла неподтверждённые утверждения в принятом ответе 3.
Подробности в `manual_review.md` этого прогона. Это демонстрация ограничений
самопроверки модели, а не успешная оценка достоверности всех ответов.

## Сравнение с Qwen

Результат Qwen на тех же вопросах: `results/20261025-234156-690366/`.
Оба автоматических контрольных случая пройдены, но ручная проверка снова
выявила ложное принятие в ответе 3. Полный разбор — в `comparison.md`.

Прогон Qwen3-14B: `results/20261026-012509-727564/`. Оба контрольных случая
пройдены, но точные непрерывные цитаты найдены только в 3 из 5 обычных ответов.
Запуск: `.venv/bin/python main.py --model Qwen/Qwen3-14B-GGUF:Q4_K_M --questions-from results/20261025-230717-434928/questions.txt`.
